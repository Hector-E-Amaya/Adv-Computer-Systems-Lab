# ECSE 4320/6320 Advanced Computer Systems: Class-wide Projects

Three performance-profiling projects, all measured on one laptop: an Intel
Core i3-1125G4 (Tiger Lake, 4 cores / 8 threads), 8 GB single-channel
DDR4-3200, a Samsung PM991a 512 GB NVMe SSD, and Windows 11 Home.

| Project | Report | Headline |
|---|---|---|
| #1 [SIMD Advantage Profiling](SIMD-Advantage-Profiling/) (110 pts) | [REPORT](SIMD-Advantage-Profiling/reports/REPORT.md) | SIMD speedup tracks lane count in L1 (saxpy f32 3.0x / 6.0x / 10.75x for SSE2 / AVX2 / AVX-512) and vanishes in DRAM (1.05x), where scalar code already saturates single-core bandwidth |
| #2 [Cache & Memory Performance Profiling](Cache-Memory-Performance-Profiling/) (185 pts) | [REPORT](Cache-Memory-Performance-Profiling/reports/REPORT.md) | L1 / L2 / L3 latency 5.0 / 14.1 / ~40 cycles, DRAM 82.5 ns; loaded-latency knee at ~72-84% of the 25.6 GB/s peak; TLB steps confirmed by VTune counters |
| #3 [SSD Performance Profiling](SSD-Performance-Profiling/) (185 pts) | [REPORT](SSD-Performance-Profiling/reports/REPORT.md) | QD=1 4 KiB random read 139 us; knee at QD 32 (126 K IOPS); Little's Law within 1-5%; device/link-side ceilings of ~0.75 GB/s read (varies by session) and ~0.15 GB/s write |

All three projects are complete.

## Common structure
Each project folder has the same layout:

| Path | Contents |
|---|---|
| `README.md` | layout, reproduce commands, **rubric map** (where each graded item is), status |
| `reports/REPORT.md` | the report, with sections ordered by rubric category, a hypotheses scorecard and limitations |
| `reports/HYPOTHESES.md` | predictions committed **before** any measurement (see git history) |
| `reports/RESULTS_TABLES.md` | every table, generated by `scripts/analyze.py` (not edited by hand) |
| `reports/NOTES.md` | chronological record of decisions, bugs found and fixed, and rejected data |
| `reports/AI-USE.md` | AI-use note: what was generated, what was checked, corrected or rejected |
| `reports/CONTRIBUTIONS.md` | the student's review concerns, with verdicts and outcomes (Projects 2-3; Project 1's are in its AI-USE) |
| `src/` or `configs/` | benchmark sources (Projects 1-2) or fio job files (Project 3) |
| `scripts/` | environment capture, build/test, sweeps, parsing, analysis |
| `data/raw/`, `data/processed/` | raw measurements and environment capture; aggregated tables |
| `plots/` | figures referenced by the report |

## Reproducibility
- Each project README lists the exact commands, in order. Toolchain: Git
  Bash, MSYS2 UCRT64 gcc 16.2 (Projects 1-2), Python 3.14 with
  numpy/pandas/matplotlib, Intel VTune 2026.6 (Project 2 counters), fio 3.43
  (Project 3).
- `scripts/analyze.py` regenerates every plot and table from the committed
  raw data; re-running it reproduces the committed outputs byte for byte.
- Correctness suites: Project 1 `scripts/test.sh` (1121 checks), Project 2
  `scripts/test.sh` (366 checks).
- **Independent re-run** ([RECHECK_2026-10-22.md](RECHECK_2026-10-22.md)): a
  fresh clone, re-measured in a later session.
  - Projects 1-2 reproduce with a median new/old ratio of 0.99-1.00 in every
    table. 73-100% of values per table are within 10%; the lowest share is
    in tables of maxima and variation coefficients.
  - Project 3's 4 KiB results reproduce within 3%, but its large-read
    bandwidth ceiling was ~30% lower. Each report discusses the values that
    moved.
- Project 3 never touches a raw device or partition: only disposable files in
  `C:\fio-test\` with direct I/O (`SSD-Performance-Profiling/reports/SAFETY.md`).

## AI use
All three projects were built with Claude Code under a batch workflow the
student approved step by step. Each project's `reports/AI-USE.md` gives the
details, and its `CONTRIBUTIONS.md` lists the student's review concerns.
